# Производительность: бюджеты и методика

## Жёсткие бюджеты (из ТЗ)

| Метрика | Бюджет | Как проверяем |
| --- | --- | --- |
| FPS | ≥ 50 на среднем Android, ≥ 30 на бюджетных | dev-оверлей + авто-качество |
| Draw calls | < 100 / кадр | `renderer.info.render.calls` в PerfOverlay |
| Tris сцены | < 120k | `renderer.info.render.triangles` |
| Текстуры | 512², KTX2, VRAM < 120 MB | `renderer.info.memory.textures` + DevTools |
| Bundle gzip | < 3 MB | `npm run size` (CI gate) |
| Первый рендер | < 2.5 с | splash timing + E2E |
| RAM | < 250 MB | `performance.memory` (Chrome Android) |
| Батарея | < 15% / 30 мин | ручной замер, Screen Wake Lock + пауза в фоне |

## Что сделано на этапе 1

- **Один контекст WebGL** на всю сессию; MSAA выключен, кант-эджи делает FXAA (экономия bandwidth).
- **Render scale** из пресета: 1.0 / 0.85 / 0.7, pixel ratio ограничен 2.0 / 1.75 / 1.5.
- **Один общий проход vignette + grain** вместо двух (экономия ~0.4 мс на Mali).
- **Bloom отключается** на low, FXAA тоже (при 0.7 render scale апскейл сам по себе сглаживает).
- **SSAO создаётся лениво** только при переходе на high и уничтожается при уходе с него.
- **Тени**: directional light, 2048 / 1024 / off, `PCFSoftShadowMap`, shadow camera привязана к арене.
- **Point lights**: бюджет ≤4, на low ≤2; факелы выключаются на уровне `visible`.
- **Instancing**: колонны — один draw call.
- **Материалы**: один набор текстур (albedo/normal/roughness) переиспользуется полом, стенами и колоннами.
- **Пауза рендера**: `pause()` останавливает RAF полностью (не «рендерим вхолостую»), это критично для батареи.
- **Stats собираются окнами 500 мс**, первый экран отбрасывается (компиляция шейдеров), UI обновляется 2–4 раза в секунду.

## Стоимость ввода (этап 2)

- Стик и камера обрабатываются в PointerEvent-хендлерах без React-рендеров; позиции пишутся в DOM через `transform`.
- Кулдаун кнопки обновляется rAF только пока идёт перезарядка (≤2 с), затем цикл останавливается.
- `getInteractionHint()` опрашивается 6–7 раз в секунду и не вызывает ре-рендер, если подсказка не изменилась.
- Инерция камеры — отдельный rAF-цикл ровно 100 мс после отпускания.
- Все жесты сбрасываются на `visibilitychange`/`blur`, поэтому фоновый режим не тратит кадры на ввод.

## Стоимость подземелья (этап 4)

- **Генерация этажа**: 500 сидов в юнит-тестах ≈ 4 с, т.е. ~8 мс на этаж в Node; в
  браузере генератор вызывается один раз при спуске, вне кадра рендера (после
  `unloadFloor`, до первого кадра нового этажа).
- **Геометрия**: 3 merged-меша (пол/стены/потолок) → 3 draw call независимо от числа
  комнат. Вершины общие для квада, поэтому ~700 тайлов пола ≈ 2.8k вершин.
- **UV**: 0.5 UV на метр в мировых координатах, одна текстура 256² на все поверхности.
- **Коллайдеры**: стены — жадные прямоугольники высотой 6 м, потолки — по слоям
  высоты, пол — один бокс. На реальном этаже 40–70 тел вместо ~2000; шаг физики
  остаётся доли миллисекунды.
- **Свет**: по одному `PointLight` на комнату, включены только ближайшие (пересчёт
  5 Гц). Бюджет: high/medium ≤4 (факел + комнаты + руна), low ≤2. Остальные
  источники выключены на уровне `visible`, поэтому не попадают в шейдер.
- **Мебель**: все повторяющиеся объекты — `InstancedMesh` (факелы, кости, щебень,
  свечи, сундуки, алтари, костры) → ~10 draw call на этаж.
- **Двери**: геометрия панелей общая на этаж, 1–2 створки на проём, 9–19 проёмов.
  Один вызов `collider.isEnabled()`/дверь/кадр.
- **Туман**: `FogExp2 0.04` отсекает дальние комнаты по альфе без отдельного прохода.

## Стоимость моделей и анимации (этап 5)

- **Пайплайн**: `npm run assets` ≈ 90 мс на 7 моделей, 343 kB GLB суммарно
  (герой 123 kB / 1.3k tris / 19 костей / 7 клипов).
- **Скиннинг**: жёсткие веса (0–1 смешивание у сустава) вместо smooth-skin — на
  мобильном GPU это дешевле (меньше ветвлений выборки матриц) и выглядит как
  стилизованные доспехи.
- **Draw calls героя**: 4 (по одному на материал: ткань, броня, сталь, руны).
- **Анимация**: один `AnimationMixer` на персонажа, ≤3 активных действий
  (уходящее + входящее + одноразовое). Клипы 0.35–2.4 с, никаких морф-таргетов.
- **Загрузка**: GLB грузятся последовательно на стадии «Модели» сплэша; при
  провале сети/404 сцена откатывается на placeholder и остаётся играбельной.
- **Кэш**: `AssetLoader` держит исходники и клонирует их через `SkeletonUtils`
  (для монстров этапа 6), геометрия общая.

## Стоимость физики (этап 3)

- Симуляция: 60 Гц, 4 итерации солвера, ≤4 подшага на кадр. Тестовая арена: 16 статических коллайдеров + 1 kinematic-капсула → шаг занимает доли миллисекунды на современных телефонах; измерять на устройстве через `performance` профиль.
- WASM: **отдельный чанк 1.67 МБ gzip**, грузится только на стадии сплэша «Движок», не блокирует парсинг стартового бандла.
- Камера: один `castRay` в кадр вместо обхода мешей (`intersectObjects`), с исключением капсулы игрока.
- Визуализация коллайдеров включается только в dev (`?physics=1`) и перестраивает один буфер линий.
- `FixedStepAccumulator` отбрасывает время при просадках >4 подшагов — телефон под троттлингом не уходит в «догоняющую» симуляцию.

## Текущие цифры (этап 3, тестовая арена)

- Bundle: **~1.9 MB gzip** (rapier 1670 + app 95 + three 145 + react 45 + telegram 18); стартовый путь без physics-чанка — ~300 кБ.
- Draw calls: ~11 (стены ×4, пол, колонны-instanced, 4 кристалла, герой ×3, факелы-свет без мешей; +1 линии в dev).
- Tris: ~6k.
- Текстуры: 3 × 256² (временный размер тестовой сцены; финальный пайплайн — 512² KTX2).

## Стоимость боёвки (этап 6)

- **Активные враги.** Потолок `maxActive = 6`. Тело врага — одна kinematic-капсула
  Rapier (0.55 × 1.7 м, как у игрока), один клон GLB и один `AnimationMixer`.
  Замер по коду: 6 × 1792 ≈ 11k tris на волну; 4 `SkinnedMesh` на модель
  (материалы делятся с кэшем ассетов) → 24 draw call на полную волну. Вместе с
  этажом (~28) и героем (4) это ~56 draw call при бюджете 100.
- **Спавн.** `EnemyDirector` вызывается раз в фиксированный шаг и делает один
  проход по плану (~9–14 точек на этаж) плюс фильтр активных — это десятки
  сравнений, не кадровая стоимость. План строится один раз при загрузке этажа.
- **Анимация.** Микшер обновляется только для видимых врагов (`update` в кадре);
  при `state === 'chase'` скорость берётся из таблицы, иначе передаётся 0 —
  лишних `crossFade` нет.
- **Эффекты удара.** Два `InstancedMesh` по 40 экземпляров (искры и «моты»):
  фиксированные 2 draw call независимо от числа попаданий, частицы в пуле
  (без аллокаций на удар). Цифры урона — пул из 12 спрайтов с собственными
  canvas 128×64: одна перерисовка и одна загрузка маленькой текстуры на удар,
  вместо DOM-узлов, которые заставляли бы браузер пересчитывать layout в бою.
- **HUD.** `useVitals` поллит снапшот раз в 100 мс и сравнивает округлённые
  значения: во время боя React перерисовывается ~2–3 раза в секунду, а не 60.
  Полосы HP/стамины — CSS-`width`, без Framer Motion (анимация 200 мс).
- **Тряска камеры.** Синусоидальный джиттер амплитудой ≤0.16 м с затуханием
  ×4/с: аддитивный оффсет к позиции камеры после `lookAt`, без RNG и без
  пост-обработки.
- **Симуляция.** ИИ, движение и урон живут в фиксированном шаге 60 Гц; кадр
  только интерполирует. Raycast линии видимости выполняется не чаще одного раза
  на врага за шаг (`distance < 2` — без raycast вовсе).

## Стоимость лута и инвентаря (этап 7)

- **Никаких сетевых запросов.** Таблица предметов (~6 кБ JSON) собирается в
  бандл; роллы — арифметика на `Math.random`, дроп монстра не аллоцирует ничего,
  кроме короткоживущего объекта результата.
- **Сундуки.** По одному GLB-клону на сокровищницу (обычно 1–2 на этаж, 96 tris).
  Клон делит геометрию и материалы с кэшем `AssetLoader`, поэтому закрытый и
  открытый сундук стоят одинаково; `dispose()` освобождает только процедурный
  фолбэк.
- **Панель инвентаря.** Открывается на паузе: кадры рендера останавливаются,
  React перерисовывается только при изменении снапшота (поллинг 150 мс, 12
  карточек максимум). Карточки — обычные кнопки с CSS-цветом редкости; иконки —
  эмодзи, без дополнительных текстур и спрайтовых атласов.
- **HUD.** Золото и счётчик предметов добавлены в уже существующий 10 Гц поллинг
  виталов: один дополнительный `setState` в секунду в худшем случае.
- **Ассеты.** `preloadRun` теперь грузит и пропсы (5 моделей, 87 кБ) — это
  добавляет ~90 кБ к сплэшу и снимает риск «сундук без модели» в рантайме.

## Стоимость выживания (этап 8)

- **Голод** — одна структура чисел и ~5 арифметических операций на фиксированный
  шаг (60 раз в секунду), то есть шум в сравнении с физикой. Никаких таймеров,
  подписок или строковых сравнений в горячем пути: тосты о смене порога
  отправляются только по фронту состояния.
- **HUD** — сытость и пайки добавлены в существующий 10 Гц поллинг виталов;
  полоса HG меняет только CSS-`width`. Кнопка пайка — обычная кнопка, без
  анимационных библиотек.
- **Экран смерти** — DOM-оверлей с fade 200 мс. Сцена в этот момент стоит, но
  цикл рендера продолжает идти, чтобы доиграть клип смерти; после ~1 с кадры
  становятся идентичными, и стоимость сводится к одному draw-проходу сцены.
- **Рестарт** — перегенерация этажа и коллайдеров занимает единицы миллисекунд
  (`DungeonScene.restartRun`), в отличие от пересоздания движка (300–800 мс на
  телефоне). Ни одного нового WebGL-контекста и ни одной новой текстуры.
- **Звука по-прежнему нет** — этап 10 добавит его вместе с измерением RAM под
  Howler.

## Стоимость босса и мета-прогрессии (этап 9)

- **Босс — одно тело.** Арена добавляет ровно одну капсулу и одну
  скиннинг-модель к тем ≤6, что уже разрешены `EnemyDirector`. Прибавка к draw
  calls нулевая: модель инстансится из того же кэша, что и обычный монстр.
- **Фазы — арифметика.** `phaseMultipliers()` вызывается только при попадании
  и при чтении `strikeDamage` (раз в удар), а не каждый кадр; аллокаций нет,
  результат — литерал из трёх чисел.
- **Полоса здоровья** опрашивается через `setInterval` 8 Гц, как и виталы.
  Пока босс не в радиусе 20 м, `getBossState()` возвращает `null` и HUD ничего
  не рендерит; ширина полосы меняется только при |Δratio| ≥ 0.002.
- **Мета — ноль кадров в бою.** `MetaState` живёт вне сцены, экран алтаря —
  статичный DOM. Запись в IndexedDB идёт сразу на покупку: это один тап на
  статичном экране, а дебаунс-окно (250 мс) теряло покупку, если WebView
  закрывали сразу после нажатия. Транзакция < 1 KB, частота — единицы за сессию.
- **Награда за забег** считается в момент смерти один раз: `stats` пишется
  fire-and-forget, экран итогов не ждёт IndexedDB.
- **Память.** Новых текстур и геометрии нет; бюджет GLB не изменился (343 kB),
  общий gzip вырос на ~4 kB (данные `progression.json` + код мета-состояния).

## Стоимость аудио (этап 10)

- **Бюджет 600 kB, факт 508 kB.** 19 файлов PCM WAV 22.05 kHz mono 16 бит
  (≈44 kB/с). OGG сжал бы в ~6 раз, но требует внешнего энкодера — ассеты
  обязаны собираться `npm run assets` в чистом окружении, поэтому взят PCM.
- **Автозагрузка в фоне.** `loadAudio()` поднимает Howler динамическим импортом
  (~10 kB gzip + контекст WebAudio) и ставит 19 `decodeAudioData` в очередь, не
  блокируя rAF: первый кадр не ждёт звук. Стадия `audio` прогресса — 0.78.
- **Ноль аллокаций в бою.** `playSound` — поиск по объекту + `Map.get` для
  троттлинга; каждая дорожка держит один `Howl`, голоса выдаёт Howler.
- **Троттлинг вместо очереди.** Удары (55 мс), шаги (120 мс), боль (220 мс):
  шесть попаданий в одном кадре дают один звук, а не шесть наложенных копий —
  именно наложение и клиппит на телефонном динамике.
- **Память.** 19 декодированных буферов ≈ 22 MB Float32 (≈11 MB в моно при
  воспроизведении) — на iOS WebView это верхняя граница комфорта, поэтому нет
  ни музыки-трека, ни слоёв амбиента: один 3.2-секундный луп.
- **Пауза.** `visibilitychange`/`blur` глушат микшер (`Howler.mute`) и
  останавливают амбиент; на возврате состояние восстанавливается, а не
  перезапускается.
- **Выключенный звук = ноль работы.** `soundEnabled: false` ставит master 0, и
  `playSound` выходит до обращения к бэкенду.

## Стоимость полировки (этап 11)

- **Хит-стоп — арифметика, а не кадры.** Заморозка масштабирует `dt` симуляции
  (`physics.step(dt * scale)`, `scene.update(dt * scale)`), таймер тикает по
  реальному времени. Пик — 0.12× на 100 мс у крита: три кадра по 16 мс вместо
  шести. Камера и `PerfMonitor` идут по реальному времени, поэтому FPS-график не
  считает хит-стоп за просадку и не запускает ложную деградацию.
- **Уровни забега — чистые числа.** `LevelTrack.addXp` — цикл по кривой
  `baseXp × growth^(n−1)`: на практике 0–2 итерации на убийство, ни одной
  аллокации. Бонусы уровня пересобираются только в момент повышения, а не
  каждый кадр.
- **Партиклы по бюджету.** `setBudget(preset.particleRatio)` меняет только
  количество спавнов: пул и два `InstancedMesh` те же, новых draw calls нет.
- **Пауза бесплатна.** Оверлей паузы останавливает rAF целиком: 0 кадров, 0
  батареи; состояние сцены не пересобирается, поэтому «Продолжить» — это
  `loop.resume()`, а не перезагрузка этажа.
- **Тост о деградации.** Качество меняется автоматически и без перезагрузки;
  новый тост стоит один React-рендер на событие (не чаще, чем раз в 8 с).

## Стоимость релиза (этап 13)

- **Иконки** — 3 PNG (12.9 + 48.8 + 38.0 kB) генерируются за ~200 мс и грузятся
  только браузером при установке PWA: на первый кадр не влияют.
- **Web manifest** — 1 kB статики, читается один раз при установке.
- **Итог бандла** — 2.49 MB gzip из 3 MB (Rapier WASM 1.67 MB в ленивом чанке,
  Howler 9.6 kB, приложение ~127 kB, модели 343 kB, звук 508 kB).
- **Сборка** — `npm run assets` 0.4–0.6 с + `vite build` ~1.3 с; CI quality-джоба
  держится в пределах 50–55 с после `npm ci`.

## Как замерять на устройстве

1. Открыть игру в Telegram, добавить `?perf=1` к URL (или запустить dev-сборку — оверлей включён по умолчанию).
2. Смотреть FPS / frame time / worst frame / draw calls / tris в верхней панели.
3. Профилировать через Chrome Remote Debugging (`chrome://inspect`) → Performance.
4. Проверять смену пресета: при стабильных < 45 FPS движок понижает tier через 2 с, повторно — не раньше чем через 8 с.

## Ограничения текущего этапа

- Нет реальных моделей (этап 5) — бюджеты tris/draw calls валидируются на примитивах.
- Частицы ограничены бюджетом пресета (`particleRatio` 1 / 0.6 / 0.4): на низком
  тарифе удар даёт меньше искр, но всплывающие цифры, тряска и звук остаются.
- Физика покрыта статикой, капсулой игрока и капсулами врагов (до 6); снаряды появятся позже и потребуют перезамера.
- Аудио — процедурный WAV без OGG-энкодера: 508 kB в загрузке вместо ~85 kB;
  при появлении энкодера в пайплайне формат меняется одной строкой в `sfx.ts`.
- Лут не летит по полу отдельными предметами: добыча сразу попадает в сумку, чтобы не заставлять игрока бегать за каждой монетой пальцем.
- Голод не влияет на скорость передвижения (только на стамину и урон) — иначе темп игры проседал бы незаметно для игрока и незаметно для профилировщика.
- Аудио не подключено (этап 10) — RAM/батарея по звуку будут измерены после Howler.
